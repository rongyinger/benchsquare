# 榜单公示 PRD

版本：1.1｜更新日期：2026-10-29｜状态：Demo 已实现，文档待评审

## 1. 项目背景

比赛详情原有排行榜只有“成绩尚未公布”占位，参赛者无法比较团队成绩，也无法确认本队是否达到上榜条件。本期参考 Kaggle 的表格结构，在 BenchSquare 比赛详情提供公开团队排行榜，统一展示名次、成员、综合得分与有效提交。当前没有可引用的使用量或效率数据，不提出提升比例。

> 公开排行榜用于展示参赛进度，不自动决定最终获奖资格。本期使用明确标注的演示成绩，“更新”只重新读取榜单并刷新时间，不提供下载。

## 2. 产品目标

通过以下场景判断本期目标是否完成。

| 目标 | 成功判定 |
| --- | --- |
| 成绩可比较 | 一队一行，综合得分降序；同分并列，筛选后保留全榜名次。 |
| 本人可定位 | 当前比赛已组队用户可识别浅黄色高亮的本队，也可仅看我的团队。 |
| 上榜条件清楚 | 至少 3 道任务通过验收且完成评分；不足时说明原因，空榜不展示空表格。 |
| 操作结果稳定 | 搜索、分页、更新均可完成；更新保留筛选与有效页码，不随机改变模拟成绩。 |
| 演示边界明确 | 系统示例标注演示数据，新建比赛不自动填充分数；榜单不改动审核或奖金记录。 |

## 3. 用户与场景

| 角色 | 场景 | 任务与结果 |
| --- | --- | --- |
| 比赛访问者 | 进入比赛详情的排行榜 | 查看公开团队成绩，搜索团队并翻页；不要求先报名。 |
| 已完成组队的参赛者 | 查找本队名次或发现本队尚未上榜 | 通过高亮或仅看我的团队定位；无成绩时看到上榜条件。 |
| 演示使用者 | 展示有成绩、本人无成绩与全场无成绩 | 切换内置演示场景，对比状态，不改变提交与审核数据。 |

团队归属沿用当前账号与当前比赛的团队关系。未组队用户可看公开榜单，“仅看我的团队”禁用。本期不新增主办方评分、改榜或发奖操作。

## 4. 需求范围

| 优先级 | 本期范围 |
| --- | --- |
| 必须 | 公开榜单、6 个表格字段、同分并列、当前团队高亮、搜索、仅看本人、10 条/页分页、更新。 |
| 必须 | 全场无成绩、本人无成绩、搜索无结果、未组队、分页边界的可见反馈。 |
| 必须 | 系统示例提供 20 支固定虚构团队及 3 种演示场景，示例与新建比赛区分。 |
| 延续现有流程 | 比赛详情入口、报名组队、账号切换、任务验收标准及奖金公示说明。 |
| 本期不做 | 榜单下载与 CSV 导出、真实评分接口、真实审核联动、修改成绩、自动发奖、团队详情跳转。 |

本期以桌面端 Demo 为主，沿用现有窄屏页面并允许表格在自身容器横向滚动；不新增生产鉴权、实时推送或性能容量数值目标。

## 5. 业务流程

进入比赛详情 → 选择排行榜 → 读取当前比赛与账号团队 → 获取榜单 → 过滤上榜资格 → 计算全榜名次 → 应用搜索和仅看本人条件 → 按每页 10 支展示。

资格口径：有效任务须验收通过且已评分，团队至少有 3 道有效任务；综合分为最高 3 道任务的平均分，按两位小数口径比较。演示直接提供固定综合分，不执行真实审核聚合。

排序口径：综合分降序；同分采用 1、2、2、4 的并列名次。同分团队按达到该分数的时间先后展示，时间仍相同则按团队标识稳定排列，不据此打破并列。有效提交次数不是排序依据。

状态：S-01 已有成绩；S-02 我的团队暂无成绩；S-03 全场暂无成绩；S-04 筛选无结果。S-02 下其他团队仍可正常上榜；S-04 清除筛选后回到完整榜单。

更新路径：点击更新 → 重新读取当前演示榜单 → 保留筛选和有效页码 → 刷新最近更新时间并提示完成。成绩保持稳定，最终获奖名单另行公示。

## 6.功能需求

| ID | 功能与可观察规则 |
| --- | --- |
| FR-01 | 比赛详情提供排行榜标签；进入后采用通栏表格布局，隐藏本标签的奖金侧栏；切回其他标签恢复原布局。 |
| FR-02 | 每队一行展示排名、团队、成员、综合得分、有效提交、最近提交；得分右对齐，前三名使用轻量标记，本人团队浅黄色高亮并显示标签。 |
| FR-03 | 只有至少 3 道已验收且已评分任务的团队上榜；综合分按最高 3 道任务平均分的两位小数口径降序比较。待审核和未通过任务不计入，提交次数不用于排序。Demo 使用预置分数，不计算真实记录。 |
| FR-04 | 同分并列，采用 1、2、2、4 形式；同分按达到分数时间、团队标识稳定展示。搜索、仅看本人及分页均保留全榜名次。 |
| FR-05 | 按团队名称实时包含搜索，忽略首尾空格与英文大小写；条件改变回到第 1 页。搜索与仅看本人可叠加。 |
| FR-06 | 已组队用户可勾选仅看我的团队；未组队禁用。本人未上榜时显示上榜条件；勾选后显示局部空态，其他团队成绩不受影响。 |
| FR-07 | 每页 10 支，展示当前页与总页数；首尾页对应按钮禁用，无结果隐藏分页。 |
| FR-08 | 点击更新后重新读取当前榜单，刷新北京时间的最近更新时间并反馈完成；保留搜索、本人筛选与有效页码。重复更新不累加团队或随机改变分数。 |
| FR-09 | 全榜为空显示成绩尚未公布；仅筛选为空显示明确原因。清除筛选同时清空关键词与本人筛选，回到第 1 页；上榜团队总数不因筛选改变。 |
| FR-10 | 内置示例提供已有成绩、我的团队暂无成绩、全场暂无成绩切换，显示演示数据标记及说明；固定 20 支团队，其中 2 支并列第 2，已有成绩场景的本队第 6。新建比赛默认空榜，不注入模拟成绩。 |
| FR-11 | 按账号和比赛分别维护页面会话内的搜索、筛选、页码和场景；切换身份不把他人的团队标为本队，不承诺刷新页面后保留筛选。 |
| FR-12 | 榜单与提交、审核、奖金记录隔离；提示最终获奖以赛事公示为准，不提供下载、导出或自动发奖入口。 |

### 榜单字段与展示对应

| 字段 | 展示与口径 |
| --- | --- |
| 排名 | 全榜名次；同分并列，筛选后不重新编号。 |
| 团队 | 团队名称与本队标识；一支团队只占一行。 |
| 成员 | 最多 3 个姓名缩写头像，其余显示人数；姓名可通过悬停查看。 |
| 综合得分 | 两位小数，越高越好；演示值不表示真实审核结果。 |
| 有效提交 | 验收通过且已评分任务数，作为参考信息。 |
| 最近提交 | 团队最近一次有效提交时间，按北京时间展示。 |
| 最近更新 | 本页面最近一次读取/更新榜单的时间，与最近提交时间区分。 |

## 7.交互与原型

| 页面/状态 | 入口与行为 | 沿用图片 |
| --- | --- | --- |
| P-01 公开榜单 | 比赛详情 → 排行榜；展示 6 列、规则、搜索、本人筛选、更新和分页。 | 桌面榜单原型 |
| P-02 本队暂无成绩 | 切换演示场景；保留他队榜单并说明本队上榜条件，仅看本人时显示局部空态。 | 沿用 P-01 布局与状态文案 |
| P-03 全场暂无成绩 | 切换全场无成绩；显示空态说明，不展示表格和分页。 | 空榜原型 |
| P-04 筛选无结果 | 输入无匹配名称或筛选未上榜本队；清除筛选回到完整榜单。 | 沿用 P-01 搜索区与空态 |

补充反馈：搜索无匹配时给出清除筛选；未组队时禁用本人筛选；第一页和最后一页的分页按钮按边界禁用；更新后反馈完成。本期为本地数据，不宣称具备网络请求失败重试或服务端实时同步。窄屏搜索纵向排列，表格容器横向滚动。

### 7.1 公开榜单（P-01）

桌面原型：顶部保留比赛信息与标签，主体通栏；本队浅黄色高亮，更新按钮位于标题右侧，页面不提供下载操作。

![桌面公开榜单](prototype-desktop.png)

### 7.2 全场暂无成绩（P-03）

空榜原型：保留比赛与排行榜标题、搜索和更新；说明任务通过验收并完成评分后上榜，表格与分页隐藏。本人有团队时额外显示本队暂无成绩的提示。

![全场暂无成绩](prototype-empty.png)

### 7.3 本队暂无成绩与筛选空态（P-02 / P-04）

本队未上榜时，在榜单上方显示团队名称、我的团队暂无成绩及至少 3 道有效任务的要求。他队成绩继续展示；仅看本人或搜索无结果时显示局部空态，并提供清除筛选。不把“筛选无结果”误写为全场尚未公布。

## 8.非功能需求

本期质量要求：桌面浏览器主要操作可完成，沿用现有窄屏适配；文本安全展示，成员身份按当前账号与比赛识别；相同数据产生稳定排序，同分显示精度与比较精度一致；本期模拟成绩与提交、审核和奖金数据隔离。

正常操作以结果明确、状态可区分为验收，不新增未经依据的响应秒数、并发量或数据保留年限。当前为静态本地 Demo，不承诺生产鉴权、服务端评分、网络失败重试或刷新后保留筛选；这些能力不计入本期已实现范围。

## 9.验收标准

| ID | 关联需求 | 前置条件/操作 | 预期结果 |
| --- | --- | --- | --- |
| AC-01 | FR-01 | 进入排行榜，再切回概览。 | 排行榜通栏且隐藏侧栏；概览恢复原有侧栏。 |
| AC-02 | FR-02 | 已有成绩场景查看表头、本队与前三名。 | 6 个字段完整；本队高亮且有标签，分数两位小数并右对齐。 |
| AC-03 | FR-03 | 按资格规则检查待审核、未通过、不足 3 道及满 3 道的输入。 | 前 3 类不参与排名，满足有效任务数且有分数的团队进入排名；Demo 不据真实审核记录造分。 |
| AC-04 | FR-04 | 查看固定示例榜单，并搜索一支并列队伍。 | 前几名为 1、2、2、4；搜索后仍显示原名次。 |
| AC-05 | FR-05 | 输入团队名、首尾空格、无匹配关键词；叠加本人筛选。 | 按条件实时过滤且回到第 1 页，无匹配有明确说明。 |
| AC-06 | FR-06 | 已组队用户勾选本人；切换本人无成绩场景；再使用未组队用户。 | 先仅显示本队原名次；无成绩时说明上榜条件；未组队用户的本人筛选禁用。 |
| AC-07 | FR-07 | 20 支团队翻到第 2 页，再尝试边界按钮。 | 每页 10 支；第 2 页从全榜第 11 名开始；边界按钮禁用。 |
| AC-08 | FR-08 | 保留搜索条件或第 2 页，重复点击更新。 | 筛选与有效页码保留，最近更新时间刷新，有完成提示；成绩不随机变化，不重复增加团队。 |
| AC-09 | FR-09 | 全场空榜与搜索无结果分别进入，再清除筛选。 | 全场空榜无表格和分页；筛选空态说明原因；清除筛选回完整榜单第 1 页。 |
| AC-10 | FR-10 | 切换 3 种演示场景，再进入新建比赛。 | 内置场景有演示标记；新建比赛不自动出现虚构分数。 |
| AC-11 | FR-11 | 在比赛 A 搜索，切换比赛 B；再切换当前账号。 | 比赛和账号的筛选状态分开，本队标识按当前身份读取。 |
| AC-12 | FR-12 | 查看更新前后的提交、审核与奖金记录，以及榜单操作区。 | 记录未被榜单改写；无下载与导出按钮；页面说明获奖另行公示。 |
| AC-13 | FR-02/05/07 | 在窄屏查看搜索、筛选和表格。 | 控件可操作；表格在自身容器横向滚动，整页不横向溢出。 |
