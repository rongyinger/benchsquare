# benchsquare 前端交互原型

当前首页按赛事运营纪要调整为专业数据众包与赛事协作入口：区分数据需求方和参赛者，强调小组生产、交付验收与按规则获得报酬。社区围绕组队招募、规则答疑、参赛经验展开。首版奖励发放采用运营线下处理；原有模拟托管仅作为早期架构演示保留，不代表真实资金服务已接入。首页与赛事数据仍为演示内容。最新视觉调整位于 `platform-focus.css`。

依据 `docs/architecture/ALE比赛整体功能架构.html` 及关联字段文档设计，借鉴 Kaggle 的侧边导航、白色留白、卡片式赛事发现与详情标签页。

## 打开

在项目根目录执行 `node frontend/serve.cjs`，访问 http://127.0.0.1:4173/frontend/ 。也可直接打开 `frontend/index.html`；推荐 HTTP 预览以获得稳定的本地存储行为。

无 npm 依赖、无构建步骤。字体来自原项目文档资源。

## AI 评测任务提交 Demo（2026-10-22）

入口：[提交任务](http://127.0.0.1:4173/frontend/submission.html#new)、[我的提交](http://127.0.0.1:4173/frontend/submission.html#list)，首页侧栏也可进入。沿用现有原生 JavaScript 技术栈、品牌色与本地字体，无新增运行时依赖。

支持分区填写、三类附件选择/拖拽/删除、草稿、校验定位、安全 Markdown 与公开/私有预览、模拟编号、详情、修改重提、历史摘要、状态筛选及模拟人工初审与终检。数据保存在当前浏览器 localStorage，File 对象仅留在当前页面会话，刷新后必须重选或删除；示例文件明确为占位文件。不执行附件，不接真实后端、Harbor 或质检服务，不对外提交数据。

原型仍可直接提供静态文件；现在也可在根目录执行 `node frontend/build.cjs`（或 `npm run build`），检查所有业务 JS 语法并输出 `dist/frontend/` 静态副本。根目录 `npm test` 执行原有检查及新增模型检查。浏览器回归需本地服务和现有 Playwright，详见 `docs/submission-fields.md`，测试不会自动安装依赖。

字段字典、数据结构、样例依据、task 初步映射与待对接事项见 `docs/submission-fields.md`。

## 已实现

- 赛事广场：关键词搜索、领域筛选、排序、响应式布局。
- 赛事详情：概览、规则、赛程奖励、团队、排行榜空状态。
- 报名和组队：确认规则后待组队；创建团队才正式参赛；申请保持待审核，可撤销；截止后禁止组队。
- 创建向导：六模块、本地草稿、字段校验、日期顺序和预算校验、预览提交。
- 主办方中心：赛事管理、方案查看、草稿编辑、撤回、补正重提与数据概览。前台不提供平台审核操作。
- 本地通知、参赛记录与草稿刷新后保留。

## 范围

本项目是单浏览器前端交互原型，使用 `localStorage` 和示例数据；不是生产服务。未接入真实身份、权限隔离、服务端草稿、版本并发控制、支付与托管、通知投递、生产多用户服务、Task 生产、评分和发布后变更审核。审核工作台已从前台删除，原 #admin 路由不再提供审核页面。所有金额和比赛均为示例，不发生交易。

初版向导默认启用排名奖励，自定义奖励可选；暂不提供移除排名奖励的高级配置。六模块的完整业务约束与后端权限仍以架构文档为准。报名与任务开始时间按所给报名流程要求串行配置。

主页面文件：`index.html`、`styles.css`、`app.js`。

## 平台首页
新增默认首页（#discover）与社区页（#community），顶部导航为发现、赛事、社区。原赛事广场保留在 #explore。首页提供领域筛选跳转；社区支持示例话题筛选和文章阅读，尚未接入发帖评论。页面使用 portal.js 和 portal.css。


## 半年仿真数据
数据集中在 demo-data.js：18 场赛事和 18 条关联讨论，覆盖 2026 年 10 月至 2027 年 3 月。所有组织、作者、金额和参与人数为虚构。赛事状态根据当前时间计算，未来社区讨论标注为预排话题；赛事与社区均可按月份筛选。用户创建的本地记录不会被替换。


## 报名与组队工作台（2026-10-20）

- participation.js 提供按演示用户隔离的报名、团队、申请、邀请与通知记录，迁移原有本人报名及团队数据。
- 我的比赛分为报名的比赛、组队邀请、我的申请；展示审批中、已同意、已拒绝、已撤销、已失效。
- 队长查看本赛事已报名且未组队用户，发送邀请；处理本队申请、移除普通成员、移交队长。普通成员可退队。
- 右上角通知与个人信息内通知中心使用同一消息列表，支持未读标记、全部已读与跳转对应记录。
- 截止后锁定团队和队长，未组队报名失效；所有成员变更与入队操作拦截。
- 右上角个人信息提供演示身份切换和当前比赛模拟截止，场景有明确提示。模拟截止会使待处理记录失效，恢复真实时间不恢复历史记录。
- 所有示例用户和交互仅在当前浏览器保存，不发送外部消息，不代表生产权限或后端并发保障。

## 主办方中心

主办方中心位于探索分组，与赛事广场、我的比赛并列。赛事管理用于创建和管理本人比赛、查看方案和处理状态；数据概览仅统计本人创建赛事的浏览器内报名与有效团队数据。Task 提交、浏览量与评审数据尚未接入，页面明确标注。已移除审核工作台入口、路由和审核决定/发布的操作界面。

已移除已收藏比赛导航、收藏页路由与卡片收藏操作；旧浏览器缓存仍可读取，不影响报名和团队记录。

## 专家名片与个人中心
头像菜单提供专家名片、资料编辑、通知中心、账号设置和演示退出。名片展示昵称、专业方向、机构、职业、技能、简介与项目经历；组队成员、申请者及待邀请参赛者可查看名片。资料按演示身份保存在浏览器，联系方式仅在账号设置显示。真实认证、账号绑定、邮件发送与跨浏览器公开访问尚未接入。原型身份与截止场景设置移至左侧底部的演示设置。

## 参赛工作台与个人任务提交（2026-10-23）

统一从侧栏“我的比赛”进入具体比赛的工作台，在“任务与提交”内查看草稿、提交状态及历史版本。侧栏不再单列“参赛工作台”和“我的提交”。入口：`index.html#mine`；旧 `#workbench` 和 `#submissions` 汇总入口兼容跳转至“我的比赛”。

- 工作台展示比赛提交时间、团队成员、任务统计、任务列表及六项提交规范；未完成报名组队不能进入团队工作区。
- 任务通过 URL 中的 competition 与 team 绑定比赛和团队，记录保留 competitionId、teamId、ownerId 与 updatedBy。每位参赛者均可独立创建、保存、正式提交及重提自己的任务，无需队长确认。记录以 ownerId 标识本人，保留比赛与团队关联。
- 提交前重新检查当前演示身份、成员关系、任务归属和赛程；未开始或已截止时仅可查看。演示赛程单独存储，不改变报名组队截止场景。
- 重提保留完整表单与附件元信息快照，支持查看历史版本。已提交任务另存修改草稿时保留原提交状态和内容，正式重提后形成新版本。
- 不同参赛者的列表、详情与恢复缓存隔离（含同队成员）；独立提交体验保留在 submission.html，不混入团队记录。多页面更新发现冲突时提示刷新，避免覆盖已变化的团队任务。
- “创建 / 打开演示工作台”显式生成独立演示比赛、当前身份的演示团队，并开启模拟提交中；不会自动替用户报名现有比赛。
- 附件仍仅保存在表单页会话内存，刷新或离开表单页后须重新选择；不上传、不执行、不接真实质检。所有角色与可见范围为浏览器本地演示，未实现生产权限及多人同步。

验证：`node frontend/workbench-model.test.cjs`；浏览器回归 `node frontend/workbench-browser.test.cjs`，Playwright 与浏览器配置沿用已有提交测试。


## 任务初审与终检流程（2026-10-23）

任务提交成功后显示待初审；人工初审通过后进入终检中；平台确认已通过、需修改或未通过。任务详情提供单独标注的本地演示审核操作，退回或不通过必须填写原因；重提保留历史并重新进入待初审。

赛程六节点统一为报名开始、报名结束、任务提交开始、新增提交截止、补正截止和结果公示。补正截止及公示时间未发布时显示待确定。截止后禁止新增；原任务需修改且补正时间有效时可继续补正。数据库、附件上传、真实审核授权及终检结果回传尚未接入。

正式要求见 `docs/prd/交付版/任务提交与审核PRD.md`。


## 比赛详情侧边提交面板（2026-10-26）

组队完成后，比赛详情右上角显示“提交数据”。点击后在详情页右侧打开提交面板，支持任务表单、附件、保存草稿、我的提交与草稿、修改重提及版本记录。我的比赛内同步使用“提交数据”入口，原参赛工作台页面入口已移除；旧工作台链接兼容进入比赛详情和提交面板。移动端面板占满屏幕。

草稿沿用原存储结构，按比赛、团队和个人身份隔离；未保存内容关闭前提示，文本支持恢复缓存。已保存附件名称会恢复，实际附件刷新或关闭面板后须重新选择。既有赛程与权限校验保留。浏览器回归：`node frontend/workbench-browser.test.cjs`。
