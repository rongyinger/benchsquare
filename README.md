# Benchsquare Demo

专业数据众包与赛事协作平台的前端交互演示，使用原生 HTML、CSS 和 JavaScript，无需安装 npm 依赖。

支持赛事发现、报名组队、主办方中心、个人资料、任务提交及模拟审核。演示数据保存在当前浏览器。参赛简历按演示身份保存在 IndexedDB，可在后续报名时复用。本项目尚未接入服务端身份认证、远程文件上传和支付服务。

比赛详情的排行榜支持搜索团队、仅看我的团队、同分并列、前十名展示、其余排名折叠和更新。[排行榜 PRD、流程图与原型图](docs/leaderboard/README.md)。

比赛详情的「团队」页新增队内可见的成员贡献明细，展示每位成员已提交、已录用和审核中任务数；同一任务补正不重复计数，不公开个人占比或私有材料。[成员贡献明细 PRD](docs/team-contributions/README.md)。

比赛详情的“提交数据”和个人数据看板的“新建草稿”都支持 Harbor 压缩包和 ALE 任务格式。ALE 任务格式包含任务信息、材料与参考结果、验证标准和诚信承诺。[任务提交 PRD、流程图与原型图](docs/submission/README.md)。

主办方中心的“赛事管理”直接展示 8 场具体示例赛事，打开 <http://127.0.0.1:4173/frontend/#organizer> 即可查看。发布状态与赛事进度分别展示，覆盖报名中、待开赛、进行中、审核补正中、已结束，以及审核中、待付款、草稿。从赛事名称进入团队管理，查看该赛事的团队、正式任务、版本与操作记录；已发布赛事与待发布赛事分组展示；点击已发布赛事名称进入管理，点击“赛事信息”进入对应赛事主页。列表不再展示“操作”列。未上线赛事点击“查看进度”展示完善方案、平台审核、奖金托管、上线确认、发布成功五步发布进度。每场示例按当前身份分别保存，恢复本赛事示例不会改动其他赛事、原比赛或个人草稿。团队详情下方可按当前赛事阶段测试成员提交资格，不实际新增任务；报名中和待开赛不可提交，补正期只允许本人需补正任务重提，已结束不可提交。旧的团队演示地址仍可访问首场赛事。

## 本地运行

安装 Node.js 24 后，在项目目录执行：

```sh
node frontend/serve.cjs
```

打开 <http://127.0.0.1:4173/frontend/>。

## 检查与构建

```sh
npm test
npm run build
```

构建输出位于 `dist/`，包含首页入口、`frontend/` 和页面所需字体资源。

## GitHub Pages 发布

1. 将项目推送到 GitHub 仓库的 `main` 分支。
2. 在仓库 **Settings → Pages → Build and deployment → Source** 中选择 **GitHub Actions**。
3. 在 **Actions** 页面运行 **Deploy demo to GitHub Pages**，或推送一次新提交。
4. 工作流成功后，在 **Settings → Pages** 中打开网站链接。

后续推送到 `main` 会自动检查并发布。配置遵循 [GitHub Pages 自定义工作流文档](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。

仓库忽略生成目录、预览截图、日志及本地参考资料，仅包含演示源码、测试和必要资源。

团队详情保留“提交数据”和“操作记录”两个标签。操作记录汇总每条数据的正式提交、补正、审核通过、录用及团队管理事件，点击可定位对应版本；核查提示随相关数据版本展示。主办方数据详情与个人数据看板共用正式版本和审核历史组件，保留各版本材料、提交人、时间及全部已记录审核节点，不把历史补正意见作为当前版本结果。

在“我的比赛”底部点击“打开拉黑申诉 Demo”，或访问 <http://127.0.0.1:4173/frontend/#competition/blocked-team-demo>，可体验进行中赛事的团队拉黑拦截。点击“提交数据”展示企业微信申诉弹窗；“模拟解除拉黑”恢复原提交流程，“恢复拉黑状态”可重复测试。限制覆盖全队的新提交和补正重提，保存草稿和历史内容保留，表单最终提交会再次读取最新团队状态。报名确认后会提示扫码加入赛事群，详情页从报名开始至赛事结束前保留“赛事交流群”入口。本地二维码仅包含演示文字，不关联真实企业微信或群聊。
